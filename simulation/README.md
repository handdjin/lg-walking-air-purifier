# 2D 공기청정기 이동 시뮬레이터

가상 주거 공간에서 공기청정기의 이동을 구현한 Python 모듈입니다. A* 알고리즘으로 벽과 장애물을 피하는 최단 경로를 탐색하고, 경로를 따라 한 칸씩 이동합니다. Python 표준 라이브러리만 사용하며 별도의 패키지 설치가 필요하지 않습니다.

## 주요 기능

- 거실·주방·침실로 구성된 2D 격자 지도
- 벽·문·장애물을 고려한 A* 최단 경로 탐색
- 단계별 이동과 현재 위치·목적지·남은 경로 조회
- 이동 중 목적지 변경
- 잘못된 요청이나 도달 불가 목적지에 대한 오류 처리
- 터미널 시연과 자동 테스트

## 실행 방법

`simulation/` 폴더가 포함된 프로젝트 루트에서 실행합니다.

```sh
python3 -m simulation.demo
```

거실 → 주방 → 침실 → 거실 순서로 이동하며 각 단계의 지도와 좌표를 출력합니다. 출력 사이에 대기 시간을 두려면 `--delay` 옵션을 사용합니다.

```sh
python3 -m simulation.demo --delay 0.2
```

`--delay`의 단위는 실제 시간의 초이며, 시연 출력에만 적용됩니다. 시뮬레이션의 가상 시간이나 물리적 이동 속도를 의미하지 않습니다.

테스트 실행:

```sh
python3 -m unittest discover -s simulation/tests -v
```

테스트는 경로의 최단 거리, 장애물 회피, 단계 이동, 목적지 변경, 오류 발생 시 상태 보존 등을 검증합니다.

## 지도와 좌표

기본 지도는 15열 × 11행입니다. 왼쪽은 거실, 오른쪽 위는 주방, 오른쪽 아래는 침실입니다.

```text
###############
#......#......#
#..XX..#..XX..#
#......D......#
#......#......#
#..X...########
#..X...#......#
#......#..XX..#
#......D......#
#......#......#
###############
```

| 기호 | 의미 | 이동 가능 여부 |
|---|---|---|
| `#` | 벽 | 불가 |
| `X` | 장애물 | 불가 |
| `.` | 방의 바닥 | 가능 |
| `D` | 문 | 가능 |
| `R` | 터미널에 표시되는 청정기 | 현재 위치 표시용 |

좌표는 `[x, y]` 형식입니다. 왼쪽 위가 `[0, 0]`이며, 오른쪽으로 x가 증가하고 아래쪽으로 y가 증가합니다. 지도 문자열은 `grid[y][x]`로 접근합니다. 이동은 상하좌우로만 가능하며 한 칸의 이동 비용은 1입니다.

방 영역의 `bounds`는 `[x_min, y_min, x_max, y_max]`이며 양 끝을 포함합니다.

| 방 코드 | 이름 | 도착 좌표 |
|---|---|---|
| `living_room` | 거실 | `[2, 4]` — 초기 위치 |
| `kitchen` | 주방 | `[11, 3]` |
| `bedroom` | 침실 | `[11, 8]` |

문은 `[7, 3]`, `[7, 8]`에 위치합니다. 문 칸은 특정 방에 속하지 않으므로 해당 위치에서 `current_room`과 `room_name`은 `None`이며, JSON으로 변환하면 `null`입니다.

지도 정의는 `house_map.json`에서 관리합니다. 화면을 구현하는 클라이언트는 `get_map()`의 반환 데이터를 사용해 시뮬레이터와 동일한 지도를 표시할 수 있습니다. 지도 변경 사항은 새 `Simulator` 인스턴스를 생성할 때 반영되며, 실행 중 지도 편집은 지원하지 않습니다.

## 사용 예제

```python
from simulation import Simulator

simulator = Simulator()
map_data = simulator.get_map()

# 목적지까지의 경로를 생성합니다. 현재 위치는 아직 바뀌지 않습니다.
state = simulator.move_to("kitchen")

# 호출할 때마다 한 칸씩 이동합니다.
while state["status"] == "moving":
    state = simulator.step()

print(state["current_room"])  # kitchen
print(state["position"])      # [11, 3]
```

위 반복문은 전체 이동을 검증하는 예제입니다. 화면에 이동 과정을 표시하려면 서버에서 일정한 간격으로 `step()`을 호출하고 각 단계의 상태를 클라이언트에 전달합니다.

## 인터페이스

| 함수 | 설명 |
|---|---|
| `get_map()` | 지도 크기, 격자, 범례, 방 영역·도착점, 시작점 반환 |
| `get_state()` | 현재 상태 사본 반환. 위치를 변경하지 않음 |
| `move_to(room)` | 현재 위치에서 목적지 방의 도착점까지 경로 예약 |
| `step()` | 경로가 남아 있으면 한 칸 이동하고 상태 반환 |
| `render_map()` | 청정기 위치를 포함한 터미널용 문자 지도 반환 |

초기 상태:

```json
{
  "current_room": "living_room",
  "room_name": "거실",
  "position": [2, 4],
  "destination": null,
  "status": "idle",
  "remaining_path": [],
  "remaining_steps": 0
}
```

| 필드 | 의미 |
|---|---|
| `current_room` | 현재 좌표가 속한 방 코드. 문 위에서는 `null` |
| `room_name` | 현재 방의 한글 이름. 문 위에서는 `null` |
| `position` | 현재 좌표 `[x, y]` |
| `destination` | 요청한 목적지 방 코드. 도착 후에도 유지 |
| `status` | 이동 중 `moving`, 남은 경로가 없으면 `idle` |
| `remaining_path` | 현재 칸을 제외한 다음 칸부터 도착점까지의 좌표 목록 |
| `remaining_steps` | 도착까지 남은 이동 칸 수 |

### 이동과 오류 처리

- 목적지 방의 영역에 들어온 뒤에도 지정된 도착점까지 이동합니다. 도착 여부는 목적지와 `status`를 함께 확인합니다.
- 이미 도착점에 있으면 같은 방으로의 요청은 즉시 `idle` 상태를 반환합니다. 같은 방의 다른 칸에 있다면 도착점까지 이동합니다.
- 이동 중 새 요청을 받으면 현재 위치에서 새 목적지까지 경로를 다시 계산합니다.
- 잘못된 방 코드는 `ValueError`, 도달 불가 목적지는 그 하위 유형인 `NoPathError`를 발생시킵니다. 두 경우 모두 기존 위치·목적지·경로를 유지합니다.
- 반환된 지도나 상태 사본을 수정해도 시뮬레이터 내부 데이터는 변경되지 않습니다.

## 서버 및 클라이언트 연동

### 이전 버전과의 차이

이전 방 단위 구현에서는 `move_to()` 호출 즉시 방이 변경되었습니다. 현재 버전에서는 **경로만 생성하며 실제 이동에는 `step()` 호출이 필요합니다.** 기존 서버에서 이동 함수를 한 번만 호출하는 경우 연동 코드를 수정해야 합니다.

`current_room`, `room_name` 필드는 유지되지만 문 위에서는 `null`을 반환하므로 클라이언트에서 해당 상태를 처리해야 합니다.

### 권장 연동 흐름

1. 서버 시작 시 `Simulator()`를 한 번 생성하고 동일한 인스턴스를 유지합니다.
2. 지도 요청에는 `get_map()`, 상태 조회에는 `get_state()`의 결과를 반환합니다.
3. 이동 요청으로 받은 방 코드를 `move_to(room)`에 전달합니다.
4. 서버의 단일 진행 루프에서 일정한 간격으로 `step()`을 호출합니다.
5. 클라이언트는 상태를 주기적으로 조회하거나 전송받아 `position`으로 위치 표시를 갱신합니다.
6. 문 위에서는 별도의 통과 상태를 표시하고, 목적지와 `status`를 확인해 도착을 처리합니다.

상태 조회 요청마다 `step()`을 호출하면 접속자 수나 조회 빈도에 따라 이동 속도가 달라집니다. 조회와 이동 처리는 분리해야 합니다. 또한 이동 과정을 표시하려면 하나의 이동 요청 안에서 전체 경로를 즉시 완료하지 않도록 합니다.

현재 모듈은 메모리에 상태를 저장하며 다중 스레드의 동시 상태 변경을 지원하지 않습니다. 단일 서버 프로세스에서 명령과 이동 단계를 순서대로 처리하거나 서버 측 잠금으로 동시 변경을 제어해야 합니다.

## 구현 범위

현재 모듈은 고정 지도, 경로 탐색, 단계 이동과 상태 조회를 제공합니다. 실제 하드웨어 제어, 가상 시간, PM2.5 계산·측정·정화, AI 목적지 선택은 포함하지 않습니다.

FastAPI 경로, 서버 진행 루프, 모바일 평면도는 별도 애플리케이션에서 연결해야 합니다. 이동 칸 수와 물리적 거리·속도 또는 가상 시간의 관계는 아직 정의하지 않았습니다.
