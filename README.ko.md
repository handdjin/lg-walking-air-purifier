# lg-walking-air-purifier

# 선제적 AI 이동형 공기청정기

### AI 기반 선제적 자율 공기정화 시스템

## 1. 프로젝트 개요

이 프로젝트는 앞으로의 실내 공기 오염을 예측하고, 정화가 필요한 곳으로 미리 이동하는 자율 이동형 공기청정기를 소프트웨어 시뮬레이션으로 개발하는 것을 목표로 합니다.

시스템은 가상 집, D* Lite 경로 탐색, Random Forest 모델, FastAPI 백엔드, LG Airy 모바일 앱으로 구성됩니다. 공기청정기는 자동 모드에서 예측값으로 목적지를 고르고, 실제로 측정한 PM2.5로 정화 여부를 결정합니다.

이 프로젝트는 한양대학교 정보시스템학과 소프트웨어공학 수업의 일환으로 LG전자와 협력하여 진행되었습니다.

## 4. 개발 방식

이 저장소는 소스 코드 관리, 버전 관리, 팀 협업에 사용합니다.

- 현재 모든 팀원이 공용 `main` 브랜치에서 함께 작업합니다.
- 각 팀원은 맡은 부분을 개발하고 유지보수합니다.
- 변경 사항은 내용을 알 수 있는 커밋 메시지와 함께 Git 커밋으로 기록합니다.
- 변경 사항을 push하기 전에 `git pull --rebase origin main`으로 로컬 저장소를 최신 상태로 맞춥니다.
- 완료한 변경 사항은 `git push origin main`으로 올립니다.
- 다른 팀원의 작업을 덮어쓰지 않도록 병합 충돌은 신중하게 해결합니다.
- 프로젝트 보고서와 문서는 `docs/` 디렉터리에서 관리합니다.


## 5. 프로젝트 진행 상황

**현재 단계: 통합 프로토타입 및 검증**

## 8. 실행 방법

### 8.1 호스팅된 백엔드

FastAPI 백엔드는 Amazon EC2에서 실행됩니다. 앱은 기본적으로 호스팅된 데모 서버에 연결합니다. 다른 서버를 쓰려면 `mobile/.env.local`에 `EXPO_PUBLIC_SERVER_URL`을 설정하세요. 그 서버가 API 키 헤더를 요구하면 같은 파일에 `EXPO_PUBLIC_API_KEY`도 설정하세요.

### 8.2 모바일 애플리케이션

저장소 최상위 폴더에서 다음 명령을 실행합니다.

```bash
cd mobile
npm ci
npx expo start
```

QR 코드를 스캔해 Expo Go에서 프로젝트를 연 뒤, 발급받은 Cognito 계정으로 로그인합니다. EC2 백엔드에 접속해야 하므로 휴대폰이 인터넷에 연결되어 있어야 합니다.

### 8.3 API 엔드포인트

| 메서드 | 엔드포인트 | 설명 |
| --- | --- | --- |
| `GET` | `/` | FastAPI 서버가 실행 중인지 확인합니다. |
| `GET` | `/map` | 가상 집의 격자, 방 경계, 목적지 좌표를 가져옵니다. |
| `GET` | `/status` | 공기청정기의 위치, 남은 경로, 작동 모드, 측정값, 예측값, 최근 AI 결정을 가져옵니다. |
| `GET` | `/predict` | 현재 측정값으로 30분 뒤 PM2.5 예측을 만듭니다. |
| `GET` | `/history` | 기록된 이동, 측정, 정화, 시뮬레이션 이벤트를 가져옵니다. |
| `POST` | `/mode` | 자동 모드 또는 수동 모드를 선택합니다. |
| `POST` | `/move` | 수동 모드에서 목적지를 요청합니다. |
| `POST` | `/start` | 시뮬레이션을 시작하거나 다시 시작합니다. |
| `POST` | `/pause` | 시뮬레이션을 일시정지합니다. |
| `POST` | `/reset` | 시뮬레이션, 이벤트 기록, AI 상태를 초기화합니다. |
| `POST` | `/step` | 실행 중인 시뮬레이션을 테스트용으로 한 단계 진행합니다. |

**모드 선택 요청 예시 (`POST /mode`)**

```json
{
  "mode": "manual"
}
```

지원하는 모드는 `auto`와 `manual`입니다.

**이동 요청 예시 (`POST /move`)**

```json
{
  "target_room": "kitchen"
}
```

지원하는 방:

- `living_room` (거실)
- `kitchen` (주방)
- `bedroom` (침실)

EC2 백엔드가 실행 중인 시뮬레이션을 자동으로 진행하고, 모바일 앱은 폴링으로 업데이트를 받아옵니다.

## 9. 현재 구현 내용

### 9.1 가상 집 시뮬레이션

- 방 세 개로 이루어진 2D 격자 기반 집 환경
- 벽, 문, 장애물, 이동 가능한 칸 정의
- 자율 이동을 위한 D* Lite 경로 탐색과 점진적 경로 재계획 지원
- 시간에 따른 실내 공기 오염 시뮬레이션
- 자동 초기 순찰과 방별 공기질 측정
- 측정한 PM2.5에 따른 공기 정화 로직
- 서버가 제어하는 시뮬레이션과 이동

### 9.2 AI 예측과 의사결정

- 앱의 시뮬레이터로 만든 합성 데이터셋 (생활 패턴이 다른 집 6곳 × 각 60일) [데이터 규칙](ai/air_quality_rules.md)
- 시간, 방, 마지막 측정값과 측정 후 경과 시간, 최근 최대 14일 측정 기록으로 방별 30분 뒤 PM2.5를 예측하는 Random Forest 모델
- 테스트 MAE 0.571 µg/m³ (마지막 측정값을 그대로 쓰는 방법은 1.397)
- 그날 세 방을 모두 측정한 뒤부터 시뮬레이션 시간 기준 10분마다 예측
- 자동 모드에서는 "예측 PM2.5 − 이동 시간" 점수가 가장 높은 방으로 이동하고, 측정한 지 오래된 방은 다시 확인하러 감
- AI 자동 모드와 20분 고정 순찰을 9일 연속 합성 시나리오로 비교한 결과와 한계는 [정책 평가 보고서](ai/policy_evaluation_report.md)에 있습니다.

### 9.3 모바일 애플리케이션

- Cognito 로그인과 Figma 디자인 기반의 홈, 기록 화면
- 공기청정기의 위치, 목적지, 경로(있는 경우)를 보여주는 실시간 평면도
- 기기 상태, 시뮬레이션 시간, 측정 및 예측 PM2.5, AI 목적지 결정 표시
- 자동/수동 모드, 수동 목적지 선택, 시작·일시정지·초기화 조작
- 로딩 및 연결 실패 상태와 다시 연결하기 기능
- 이동, 측정, 정화 이벤트를 보여주는 활동 기록

### 9.4 백엔드 연동

- FastAPI가 공용 시뮬레이션 하나를 실행하고 REST API로 상태, 예측, 기록을 제공합니다. 모바일 앱은 폴링으로 업데이트를 받아옵니다.
- 이동 중에 모드를 바꾸면 진행 중인 경로가 끝난 뒤에 적용됩니다.
- 백엔드는 시뮬레이션 상태, 이벤트 기록, AI 결과를 메모리에 저장합니다. 초기화하거나 서버를 다시 시작하면 이전 실행의 기록이 지워집니다.

### 9.5 향후 개발

- 실제 기기에서 Cognito 로그인, 시뮬레이션 조작, 재연결 검증
- 데모 테스트에서 도착, 측정, 정화, 경로 재계획의 전체 과정 검증
